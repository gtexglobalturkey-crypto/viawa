# VIAWA Document Engine

The document engine keeps business-data collection separate from template
mapping, DOCX manipulation, and HTTP delivery.

## Contract generation flow

1. A `ContractGenerationDataSource` loads the company, exact opportunity,
   exhibition, contacts, latest immutable approved-price snapshot, and the
   canonical `participation-contract` settings row.
2. `generateParticipationContract()` performs business validation and builds a
   `DocumentMergeContext`.
3. `resolveTemplateMerge()` resolves the central Content Control tag mapping.
4. A `ContractDocxGenerationPort` applies those values to the active master
   template without modifying it.
5. The authenticated endpoint returns the generated bytes and removes its
   request-scoped temporary directory.

## Ownership boundaries

- Mapping and required-field rules live under `merge/`.
- Data access lives under `repositories/` and is supplied through
  `ContractGenerationDataSource`.
- Orchestration does not access Supabase, browser storage, HTTP, or filesystem
  APIs directly.
- DOCX package manipulation lives under `vite-plugins/document-merge/`.
- Authentication, authorization, request limits, response headers, and cleanup
  live under `vite-plugins/contract-docx-endpoint/`.

Approved-price rows are append-only. Existing snapshots are never recomputed
when exhibition pricing changes. Document settings are read from the canonical
`document_settings.id = 'participation-contract'` record and are not hardcoded
inside the endpoint.
